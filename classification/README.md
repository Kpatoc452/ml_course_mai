# Лабораторная работа №2: Классификация (Titanic)

Задача — предсказать, выжил ли пассажир Титаника (`Survived`: 1 — выжил, 0 — нет).
Основная метрика — **F1-score для класса 1**, порог сдачи — **F1 > 0.70**. Полное ТЗ — в [lab02.pdf](./lab02.pdf).

| Раздел | Что делается |

| 2. Подготовка данных | feature engineering, разбиение train/test, препроцессинг в `Pipeline` |
| 3. Метрики | функции `metrics`, `evaluate`, `tune`, `importances`; объяснение FP/FN |
| 4. Baseline | `DummyClassifier(most_frequent)` |
| 5. Модели | Decision Tree, Random Forest, Gradient Boosting, SVM, KNN |
| 6. Сравнение | итоговая таблица (leaderboard), confusion matrix всех моделей, выбор лучшей модели |
| 7. Feature importance | MDI для деревьев + permutation importance для всех моделей, вопрос о причинности |
| 8. Анализ ошибок | ошибки по группам пассажиров, разбор конкретных ошибок, проверка на утечку/запоминание |
| 9. Итоговые выводы | сводка результатов |

### Признаки

Построчные преобразования в `make_features` (не обучаются по данным, поэтому применяются до разбиения):

- `Title` — титул из `Name` (`Mr`, `Mrs`, `Miss`, `Master`, редкие → `Rare`);
- `FamilySize = SibSp + Parch + 1`, `IsAlone`;
- `HasCabin` — известна ли каюта.

Удаляются `PassengerId`, `Name`, `Ticket`, `Cabin` — это идентификаторы или почти уникальные значения, по которым модель запоминала бы конкретных пассажиров.

### Схема эксперимента (защита от утечек)

1. **Разбиение:** `train_test_split(test_size=0.2, stratify=y, random_state=42)` → 712 train / 179 test, одно и то же для всех моделей.
2. **Препроцессинг** (`make_preprocessor`) находится внутри `sklearn.Pipeline`, поэтому обучается только на train (и только на обучающих фолдах при кросс-валидации):
   - числовые признаки: медиана + индикатор пропуска (`add_indicator=True`), `StandardScaler` — только для SVM и KNN;
   - категориальные (`Sex`, `Embarked`, `Title`): мода + `OneHotEncoder`.
3. **Подбор гиперпараметров:** `GridSearchCV`, 5-fold stratified CV, метрика F1 — только на train.
4. **Выбор лучшей модели:** по повторной кросс-валидации на train (5 фолдов × 5 повторов), **не по тесту**.
5. **Тест** используется только для финальной оценки и интерпретации (permutation importance, анализ ошибок).

## Результаты (test)

| Модель | Accuracy | Precision | Recall | F1 | CV F1 (train) |
|---|---|---|---|---|---|
| SVM (RBF, C=3, γ=0.03) | 0.844 | 0.825 | 0.754 | **0.788** | 0.769 |
| Decision Tree (depth=3) | 0.832 | 0.820 | 0.725 | 0.769 | 0.758 |
| KNN (k=15, distance) | 0.782 | 0.708 | 0.739 | 0.723 | 0.739 |
| Random Forest (depth=4) | 0.799 | 0.770 | 0.681 | 0.723 | **0.771** |
| Gradient Boosting (depth=2) | 0.788 | 0.754 | 0.667 | 0.708 | 0.766 |
| Dummy (most frequent) | 0.615 | 0.000 | 0.000 | 0.000 | — |

Порог F1 > 0.70 прошли все пять моделей.

Лучшая модель по кросс-валидации — Random Forest; лучший результат на тесте — SVM. Разница между моделями меньше разброса оценки на кросс-валидации (std ≈ 0.045), так что на этой задаче они практически равноценны.

### Главные выводы

- Сильнейшие признаки — пол/титул и класс, затем стоимость билета, наличие каюты, размер семьи и возраст. Это совпадает с первичным анализом. Важность признака для модели не означает, что он причина выживания.
- Неограниченное дерево переобучается (F1 0.98 на train против 0.73 на test); ограничение глубины до 3 это устраняет.
- Масштабирование критично для SVM (CV F1 0.45 → 0.76) и KNN (0.63 → 0.73) и не нужно для деревьев.
- Модели в основном опираются на правило «женщины выживают». Поэтому FN — выжившие мужчины (особенно 1-го класса), а FP — погибшие женщины 3-го класса.
- Дерево на одном `PassengerId` даёт F1 1.0 на train и 0 на test — наглядная демонстрация, почему идентификаторы исключены.
